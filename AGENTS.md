# Repository agent guide

This is an Angular 22 modular-monolith starter. Treat this file as the entry point for repository
work; more specific `AGENTS.md` files under `src/app` apply within their directories.

## Start here

- Use Node.js 24 and the pinned pnpm version from `package.json`.
- Install with `pnpm install --frozen-lockfile` when `node_modules` is missing.
- Inspect the files you will change and nearby tests before editing.
- Keep changes inside the requested scope and preserve unrelated work in the worktree.
- Use Angular CLI generators through `pnpm ng generate ...` for new Angular artifacts.

## Architecture

| Area                        | Responsibility                                            | Allowed local dependencies           |
| --------------------------- | --------------------------------------------------------- | ------------------------------------ |
| `src/app/core`              | Application-wide configuration, state, and infrastructure | `core`                               |
| `src/app/shared/ui`         | Project-owned spartan/ui Helm components                  | `ui`                                 |
| `src/app/common`            | Domain-neutral application code shared across features    | `common`, `core`, `ui`               |
| `src/app/layout`            | Application shell and navigation                          | `layout`, `common`, `core`, `ui`     |
| `src/app/modules/<feature>` | A single product feature                                  | Same feature, `common`, `core`, `ui` |

Feature-to-feature imports are forbidden. Put genuinely shared application code in `common`,
application-wide infrastructure in `core`, and reusable visual primitives in `shared/ui`. The
enforced rules live in `boundaries.config.js`.

## Coding conventions

- Separate third-party imports from project or local imports with a blank line.
- Install third-party dependencies with exact versions; never use version ranges.
- Use standalone Angular APIs. Do not add `standalone: true`; it is the Angular 22 default.
- Use signals for local reactive state and `input()`, `output()`, and `model()` instead of property
  decorators.
- Use `inject()` instead of constructor injection and `@Service` for new root singleton services.
- Use native template control flow (`@if`, `@for`, `@switch`) and class/style bindings instead of
  `ngClass` or `ngStyle`.
- Lazy-load feature routes. Keep components focused and templates accessible to WCAG AA.
- Prefer inline templates for small components. Keep external templates and styles beside their
  component when they become substantial.

## spartan/ui

- Feature work should compose components imported from `@spartan-ng/helm/*`.
- Before UI work, run `pnpm ng generate @spartan-ng/cli:info --json` and inspect installed
  components. Confirm component APIs through the spartan MCP server; do not guess selectors.
- Prefer existing components and built-in variants. Use semantic color tokens and layout-only
  utility classes.
- Files in `src/app/shared/ui` are project-owned copies, but modify them only for an intentional
  design-system change. Do not alter them merely to satisfy one feature.
- After design-system changes or upgrades, run
  `pnpm ng generate @spartan-ng/cli:healthcheck`.

## Tests and validation

- Use Vitest and Angular `TestBed`. For component updates, act, then
  `await fixture.whenStable()`, then assert; do not force rendering with `detectChanges()`.
- Use `RouterTestingHarness` for routing behavior instead of mocking the router.
- Add or update the closest test for behavior changes and include failure or boundary cases.
- During iteration, run the smallest relevant test plus `pnpm verify:quick`.
- Before handoff, run `pnpm verify`. It is the same quality gate used by CI.
- Run `pnpm deps:graph` when dependency directions or architectural placement changes, and commit
  the updated graph files.

## Runtime and generated artifacts

- Browser runtime configuration is loaded from `public/config.json`; its supported deployment
  variables are documented in `.env.example`.
- Do not commit secrets or place private credentials in browser runtime configuration.
- Do not manually edit `dist`, coverage output, Angular caches, or `pnpm-lock.yaml`. The lockfile is
  updated by pnpm when dependencies change.
- Dependency graph SVGs under `deps` are generated by the `deps:graph:*` scripts and are committed.

## Definition of done

- The requested behavior is implemented without crossing module boundaries.
- New behavior is covered by a meaningful test.
- Accessibility and empty, loading, and error states are handled where applicable.
- `pnpm verify` passes.
- Relevant documentation, runtime configuration examples, and generated dependency graphs are
  updated when their contracts change.
